# Purplebricks

> Purplebricks is the United Kingdom's largest online (hybrid) estate agency, selling and letting
> residential property across England, Wales and Scotland on a fixed fee through local property
> experts rather than a high-street branch network. It publishes no developer portal and no API
> documentation — but its production estate serves sixteen real OpenAPI 3.0.1 documents and thirteen
> live public Swagger UIs. Every operation requires a Bearer token that Purplebricks does not issue
> to third parties. Treat this catalog as an observed, unsupported contract, not as a product.

## Access posture

- No developer portal, no partner programme, no signup, no key issuance, no OAuth token endpoint.
- Auth on every service: `Authorization: Bearer <token>`, declared as an apiKey-in-header scheme.
- No `/.well-known/` layer of any kind (security.txt, OpenID Connect, RFC 8414, api-catalog all 404).
- No status page, no SLA, no deprecation policy, no changelog, no CLI, no client SDK in any language.
- No MCP server. No GraphQL. No OData/RESO surface (the UK has no MLS).
- Errors are ASP.NET `ProblemDetails` (RFC 7807) served as `application/json`.
- No idempotency key exists in any of the 205 operations. Never blind-retry a POST.
